## DevInfo 模块化重构计划

### 目标架构

将单模块 `:app` 拆分为 5 个模块：

```
:app (入口 + DI 装配)
  └── :feature-main (页面 + ViewModel)
        ├── :ui (共享组件库 + 主题)
        │     └── :core (模型 + 纯工具)
        └── :data (采集 + 存储 + 网络)
              └── :core
```

### 模块划分

#### `:core` 模块（纯 Kotlin，无 Android 依赖）
- 来源: `model/AppModels.kt` + 根包纯数据类/函数
- 内容: `DeviceInfoItem`, `InfoCategory`, `CpuCoreMetric`, `OverviewSnapshot`, `UpdateState`, CPU 解析纯函数
- 依赖: 无

#### `:data` 模块（数据层）
- 来源: 根包 15 个文件
- 内容: `DeviceInfoCollector`, `BasePreferences`, `GitHubClient`, `UpdateChecker`, `ModuleExportHelper`, `CpuUsageSampler`, `LiveHardwareMonitor`, `BatteryObserver` 等
- 依赖: `:core` + AndroidX + Coroutines + DataStore

#### `:ui` 模块（共享 UI 组件）
- 来源: `ui/theme/*`, `ui/kit/*`, `ui/AppComponents.kt`, `ui/UiKitComponents.kt`, `ui/BlurExt.kt`, `ui/DeviceInfoIcons.kt`
- 内容: 主题系统、浮动导航栏、模糊效果、双主题基础设施
- 依赖: `:core` + Compose + Material3 + Miuix

#### `:feature-main` 模块（主功能页面）
- 来源: `ui/MainScreen.kt`, `ui/MainViewModel.kt`, `ui/DeviceInfoPage.kt`, `ui/DeviceInfoOverviewPage.kt`, `ui/SettingsPage.kt`, `ui/ThemeSettingsPage.kt`, `ui/AppDialogs.kt`, `ui/screen/about/*`
- 内容: 所有页面和 ViewModel
- 依赖: `:core` + `:data` + `:ui`

#### `:app` 模块（入口，精简）
- 保留: `MainActivity.kt`, `AndroidManifest.xml`, `res/*`
- 依赖: 上述所有模块

### 实施顺序

**Phase 1**: 创建模块骨架（4 个新模块的 `build.gradle.kts` + `settings.gradle.kts`）

**Phase 2**: 移动 `:core` 代码（模型 + 纯函数）

**Phase 3**: 移动 `:data` 代码（数据采集 + 存储 + 网络）

**Phase 4**: 移动 `:ui` 代码（共享组件库）

**Phase 5**: 移动 `:feature-main` 代码（页面 + ViewModel）

**Phase 6**: 修复构建（解决循环依赖、import 路径、编译错误）

**Phase 7**: 验证（运行测试、确保构建通过）

### 关键决策

1. **包名保持不变**: 每个模块内保持 `com.fioiu8.devinfo.*` 包名，避免大规模重命名
2. **新模块使用 `com.android.library`**: 除 :app 外都用 library 插件
3. **版本目录扩展**: 新模块依赖通过 `libs.versions.toml` 引用
4. **暂不引入 DI**: 先完成模块化，后续再引入 Hilt

### 风险评估

- **高风险**: Phase 6（修复构建）— 大量 import 和依赖需要调整
- **中风险**: 数据类从根包提升到 core 需要更新所有引用
- **低风险**: UI 模块和 feature-main 模块的移动
